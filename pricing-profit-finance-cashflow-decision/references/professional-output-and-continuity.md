# PPFC 专业输出、连续追问与选择性重算

## 1. 输出类型

| 类型 | 适用问题 | 最小专属内容 |
|---|---|---|
| `decision_card` | 单一价格、促销或预算 | 唯一结论、关键数值、红线、动作、停止、回滚 |
| `pricing_memo` | 新品、价格架构、调价 | 价格走廊、候选重算、竞争证据、执行边界 |
| `unit_economics_report` | 利润诊断 | 收入成本桥、贡献层、平均/边际、翻转点 |
| `cashflow_plan` | 资金、账期、批次 | 日期现金账、峰值资金、回正时间、压力与收缩 |
| `financial_risk_brief` | 汇率、坏账、退款 | 暴露、不可补偿项、情景、对冲或补证请求 |
| `promotion_economics_review` | 促销、活动 | 基线、增量等级、蚕食、提前购买、现金、停止 |
| `parameter_change_impact` | 费率、汇率、税、物流变化 | 旧新值、闭包、差异、失效、重算、重新接受 |
| `freight_cost_breakdown` | 路线比较 | 分段计费重、档位、最低收费、附加费、币税、失败段 |

所有输出共享同一个报告信封。类型只增加专属内容，不得删除强制字段。

## 2. 强制报告合同

报告必须包含：当前唯一结论及历史引用；对象、范围、时点、版本和状态；事实、假设、证据、反证、冲突与缺失；不行动基线和候选；公式、输入、单位、币税与计算哈希；参数快照与命中规则；价格瀑布、利润桥、现金和库存口径；平均与边际；注册指标定义；敏感性、压力、翻转点和最大损失；归因与增量分离；动作、负责人、时限、成功、停止、回滚和退出；允许/禁止用途。

`validated` 经济结论不代表接收业务域已经接受。缺少停止、回滚、退出、血缘或计算绑定的报告只能是 `draft/inconclusive/blocked`。

## 3. 连续追问状态

每次追问创建不可变 `turn_id` 和变更事件，不直接修改历史结论。状态包保持：

- 唯一 `current_decision_id`；
- 不可变历史版本及 `supersedes` 链；
- 当前对象版本、输入哈希、参数快照、模型版本和报告哈希；
- 已接受、待接受、过期、阻断和撤销状态；
- 上一轮事实、假设、候选、动作与未决事项。

追问分为：

1. `clarification`：补充说明但不改变权威输入，不重算。
2. `evidence_update`：证据或数据改变，重算依赖闭包。
3. `parameter_refresh`：费率、汇率、税或物流规则改变，旧结论过期。
4. `scope_change`：SKU、国家、平台、渠道或时间窗改变，创建新对象版本。
5. `scenario_override`：只改变方案层，不覆盖事实层。
6. `accept/reject`：由有主权的接收方改变接受状态，不改变计算。
7. `execute/observe`：记录业务动作和结果，不反向改写决策时点事实。
8. `rollback`：恢复指定已验证版本作为新的当前版本，并记录原因；不得删除中间历史。

## 4. 选择性重算

变更事件从依赖图计算有向闭包：

`参数/事实 → 成本与收入 → 价格/利润/库存/现金 → ROAS/ACOS/CAC/ROI → 动作边界 → 报告`

只允许重算闭包内节点。输出必须列出：

- 变化前后值及首次受影响时间；
- 受影响和明确未受影响的对象与指标；
- 需要失效、重算、重新接受或回滚的决策；
- 新旧输入哈希、参数快照和模型版本；
- 同输入重放的幂等键。

模型合同、单位、税语义或对象身份变化属于破坏性变化，必须升级版本并完整重算。参数数值变化不得伪装成模型版本变化。

## 5. 唯一当前结论与失败纪律

同一决策链恰好一个 `is_current=true`。新增当前版本必须让旧版本成为 `superseded`；回滚也创建新版本，而不是重新激活或覆盖旧记录。发生对象冲突、循环依赖、未知变更节点、输入哈希漂移、重算结果缺失或两个当前版本时一律 `blocked`。
