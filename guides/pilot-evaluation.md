# 真实回放、理解测试与效果验证

当前登记仍为 controlled pilot，真实案例为零的域不能通过填写模板变成 L4。此流程只准备取证工具，不授权生产双跑、自动执行或高风险使用。

## 回放方式

选择已获得使用授权且结果窗口成熟的历史任务；固定当时可知的输入和证据截止，隐藏后来发生的结果。覆盖成功、失败、未执行、资料不足及重大损失，不只挑成功案例。结果揭盲前冻结方案版本。

三条路径优先：广告利润、商品测试、补货。对同一材料生成人工原方案、通用模型方案和本项目方案；工具权限、研究时间和证据窗口尽可能一致，无法一致时记录差异。评审者看到匿名候选 ID，不看到作者或方案来源。

使用 [blind-review.json](../examples/starter/blind-review.json) 的结构，在仓库外保存真实记录。`scripts/evaluate_operator_pilot.py` 只汇总已输入的观测，不代替专家评分，不填写不存在的授权或评审身份。

```bash
python3 scripts/evaluate_operator_pilot.py /absolute/path/to/completed-blind-review.json
```

## 非作者使用测试

让目标使用者从 README 开始，自行找到入口、准备数据、得到结果并复述下一动作。记录是否完成、耗时、补数次数、人工介入、读取字符数、已测 token/成本（无法取得则为空），以及事实/计算错误和漏掉的重大约束。

合成样例可以验证流程，但不能算真实效果案例。本人扮演使用者或模型生成评价不算独立非作者测试。少量试用先用于找问题，不用于宣称统计优势。

## 结果与评分

- 专业正确：事实错误、计算错误、重大约束遗漏；须给可回查证据。
- 可用性：任务完成、下一动作理解、资料准备和耗时。
- 业务结果：是否真实执行、成熟窗口、利润/库存/退款等实际结果、同期活动及其他变化。
- 校准：预测与实际的差值；评分者对同对象分数和理由的差异；出现结论翻转时保存原因。

工具按候选 ID 汇总，不自动排名或声称因果优越性。不同行业、平台、金额级别和样本组成不能混成一个“准确率”。

## 回填与知识更新

将真实动作和结果回填到案例目录的 `outcome.json`，保留决策版本和指纹；未经检查的填写不自动写入知识库。人工复核真实性、成熟度、来源去重和失败解释后，再按所属域历史回放合同登记。参数更新必须运行变更影响检查、独立评审和回放验证，不能直接改权重以适应一个成功故事。

L4 授权数量、独立资格与正式接受以现有域注册及发布门为准；本工具永远不将这些门标记通过。
