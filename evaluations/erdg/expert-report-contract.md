# ERDG 专家报告深度合同

每个执行模式必须独立交付，不得仅替换标题复用同一报告。

## 所有报告共同必需

1. 评测案例ID、复算ID、规范输入哈希与实际复算输出哈希；绑定缺失、过期或无法由注册执行器复现时报告无效；
2. 规范对象、版本、国家、平台、主体、生命周期和 `as_of_time`；
3. 决策问题、ERDG主权边界、参与域和禁止越权；
4. 输入质量以及 missing、zero、invalid、withheld、not applicable 的区别；
5. 事实、授权数据、推断、假设、反证、冲突和过期证据；
6. E0—E8适用层、现金、平均/边际、不行动基线和翻转阈值；
7. 不可补偿红线、可比较风险、尾部情景和剩余暴露；
8. Claim、Decision、Action、Replay各自状态；
9. 至少两个候选与不行动方案；
10. 动作对象、负责人、批准、顺序、资源、依赖和动作上限；
11. 成功、停止、回滚、退出、观察窗口和结果回填；
12. 计算版本、输入/输出哈希、影响闭包和唯一当前态；
13. 动态事实、生产阈值和L4的限制。

## 模式专属深度

| 模式 | 必须增加 |
|---|---|
| single_skill | 单一专业问题的完整机制、计算、反例和动作闭环 |
| cross_skill | envelope、主权冲突、接受状态、部分失败和目标域重算 |
| composite | 三个以上约束的组合、候选集合、红线瀑布和动作排序 |
| multi_turn | Information Delta、preserve/recompute、历史版本和唯一current |
| complex | 多主体、多币税、多时间窗或多层对象的守恒与隔离 |
| extreme | 不可补偿极端冲突、事故冻结、恢复与退出 |
| stress | 规模、性能、幂等、确定性、边界和失败资源上限 |

报告不得以术语密度、篇幅或固定锚点代替实质机制。每个主结论必须连接证据、确定性计算或明确不可计算原因、反事实、动作和停止规则。
